MSc project #4 · Semester project · Summary

Does grounded multimodal retrieval beat a single image model?

Summary: the data, the three starter apps P1–P3, the built system G, the reference systems S0 and R0, and the main results

Antal Ádám · Supervisor: Dr. Alwahab Dhulfiqar Zoltán

October 2026

Short version of the final presentation. The question: on chest X-rays, does a system that combines the image, clinical text and retrieved similar cases do better than a single specialist image model? Every system was run once on a held-out test set, with every choice fixed beforehand.

The premise

The question and the eight systems

Does adding clinical text and retrieved similar cases to an LLM make it better than one specialist image model at reading chest X-rays?

Eight systems, the same six findings, the same 400 test studies · every choice fixed on training / validation data first · test set used once

The assigned thesis title asks for a multimodal, explainable decision-support prototype. This project turns it into a test: is a multimodal retrieval system actually better than a single image model? A “no difference” result would also count as an answer. The three starters, the built system G with two ablations, and two reference systems without an LLM, in the order the deck presents them.

1 · The data

IU X-Ray (Open-i)

What it is

  • Chest X-rays with their radiology reports from two Indiana University hospital systems, published by the US National Library of Medicine
  • Outpatient studies: mostly normal or mild findings
  • One study per patient, by design of the collection

What one study contains

  • A report in XML: COMPARISON, INDICATION (the clinical question), FINDINGS, IMPRESSION
  • Usually a frontal and a lateral image (PNG), with no label saying which is which
  • Manual MeSH codes added by the dataset’s authors

Size and licence

  • 3,955 reports, 7,470 images · CC BY-NC-ND 4.0 · Demner-Fushman et al., JAMIA 2016

CXR2130: frontal (left) and lateral view. Source: Open-i, CC BY-NC-ND 4.0

INDICATION Dyspnea and edema.

FINDINGS Cardiomegaly is present. There is interstitial pulmonary edema … There is an oval, 17 mm nodular opacity … There is a XXXX posterior effusion. …

IMPRESSION 1. Cardiomegaly with mild interstitial edema and XXXX posterior pleural effusion. 2. 17 mm nodular opacity in the left lung …

MeSH codes → labels Lung Opacity, Cardiomegaly, Pleural Effusion

The Indiana University chest X-ray collection, distributed by the US National Library of Medicine through Open-i. Two hospital systems, outpatient studies, one study per patient. Each study is an XML report with four sections and usually two images. The authors attached manual MeSH codes, which became the ground truth. “XXXX” marks text removed during de-identification. The example, CXR2130, is used throughout the deck.

2 · The starter apps

P1: image → structured report

As shipped

  • Agno agent with Gemini 2.5 Pro and a DuckDuckGo search tool; no question input
  • One fixed prompt: a report in five sections · 1 Image Type & Region · 2 Key Findings · 3 Diagnostic Assessment · 4 Patient-Friendly Explanation · 5 Research Context (web search for literature)

Changes → P1-adapted-ns

  • Batch runner; gemini-3-flash-preview
  • Web search off (not reproducible) and section 5 removed: it still ordered the missing tool, and 62% of pilot calls failed
  • The fixed question appended to the prompt

G: how it works

→
One Gemini callgemini-3-flash-preview; JSON schema enforced; no tools
→
Validatesix findings · 0 ≤ p ≤ 1 · every cited ID was given

Per finding, G returns

  • status present / absent / uncertain → yes / no, as for the starters
  • probability 0–1 → AUROC, and yes / no at a cut-off of 0.08, chosen on validation
  • cited case IDs which of the 10 cases support the call
  • rationale one or two sentences; plus a short impression

G does in one direct call what the starters spread over apps and agents. Retrieval comes first; the neighbours’ FINDINGS and IMPRESSION go into the prompt as text with the indication, the finding definitions and the patient’s image. The API enforces a JSON schema, and the code checks every answer afterwards. Settings were fixed before the test run: k = 10, prompt version 2 frozen after the 50-study pilot, and the 0.08 cut-off chosen on the 400 validation studies.

4 · Reference systems

Key points

  • No LLM, no text, no retrieval: the image alone
  • Zero-shot: trained only on other hospitals’ data; weights trained on Open-i (= IU) excluded
  • Best of 6 DenseNet set-ups on train (macro AUROC 0.728); padding beat the library’s centre crop
  • Cut-off per finding: every value tried on train, the best balance of sensitivity and specificity kept (Youden’s J = sensitivity + specificity − 1)

S0 is the “single image-recognition model” of the thesis question: a DenseNet-121 from TorchXRayVision, trained by others on MIMIC-CXR and never on IU data. A ResNet-50 from the same library scored higher on train but was kept as a reference only, because the plan names a DenseNet and its Lung Lesion output is untrained. Each finding gets its own Youden threshold on train, which tends to be low.

Which weights could be used

  • The weights must never have been trained on Open-i (= IU X-Ray); otherwise S0 would be tested on images it had learned from
  • The combined DenseNet “all” weights include Open-i → excluded
  • Of the single-dataset DenseNets, only CheXpert, MIMIC-nb and MIMIC-ch output all six findings → 3 candidates × crop / pad
  • Rule fixed beforehand: the highest macro AUROC on train

Why not the ResNet-50

Also never trained on IU, and clearly stronger, but its Lung Lesion output is untrained (none of its datasets defines it). Reported as a reference only, so S0 is not the best available specialist.

Padding instead of cropping

The library’s centre crop cut off chest edges on IU’s wide films.

S0 must not have learned from the test data, so only weights trained without Open-i were allowed. That ruled out the combined DenseNet weights. The three single-dataset DenseNets that cover all six findings were scored on train, with and without padding, and the highest macro AUROC was kept. A ResNet-50 from the same library, also without Open-i, was clearly better but cannot score Lung Lesion natively, so it was kept as a reference and never run on test.

4 · Reference systems

R0: retrieval alone, no LLM

EmbedBiomedCLIP turns the frontal image into 512 numbers
→
Searchcosine similarity against 2,804 train studies
→
Votescore = share of the k nearest with the finding

Key points

  • Index = train split only; a study can never retrieve itself (asserted)
  • k chosen by leave-one-out on train (each study scored from the other 2,803)
  • Cut-offs on the vote share, one per finding, chosen the same way as S0’s (Youden’s J)
  • Example CXR2130, k = 150: Lung Opacity 0.200 (threshold 0.100) → yes; Atelectasis 0.060 (0.080) → no · 4 of 6 correct
  • G uses the same index: R0’s first 10 neighbours are exactly G’s 10
R0 asks whether simply looking up similar images is already enough. Performance rises up to about k = 100 and then plateaus; k = 150 was best. Single neighbours carry little signal: k = 1 gives 0.572.

Read with care: only 324 of the 2,400 calls are “present”, so answering “absent” to everything already gets 2,076 right. Counts of correct answers reward caution: G’s own verdicts score best by missing two thirds of the findings, while S0 and R0, tuned to catch findings, miss fewest but raise most false alarms. The gain rests largely on Lung Lesion (+0.19), where S0’s label does not fit IU’s codes. The firmer finding: the retrieved cases and indication make Gemini better than Gemini on the image alone, and that holds without Lung Lesion (+0.040).

Conclusions

Conclusions

Q1

None of the starters ran on chest X-rays as shipped. Adapted, they answer every study, but their verdicts are coarse; P3 never reads the patient’s image.

Q2

G combines P1’s systematic reading, P2’s retrieval and P3’s citations, and adds the clinical indication, a probability per finding and machine-checkable citations.

Q3

G beats the planned specialist (+0.049 macro AUROC), but mostly on Lung Lesion, where the specialist is handicapped. Robust: cases + context make Gemini better than Gemini on the image alone, and its citations are 81–96% verifiable.

Three answers. Q1: none of the starters works on chest X-rays out of the box. Q2: G combines the starters’ strengths and fills their gaps. Q3: G beats the planned specialist on the pre-declared criterion, but mostly on one finding; the robust result is within the design. Main limits: S0 is the planned DenseNet, not the strongest specialist; one hospital collection; Gemini has probably seen this dataset.
